# برنامه اجرای NavraCar V2

## اصل اجرا

بازطراحی در چند PR مستقل انجام می‌شود. هر مرحله ابتدا در Staging بررسی و فقط پس از پذیرش مالک به Production ارتقا می‌یابد. سند طراحی، مجوز تغییر فرمول قیمت‌گذاری یا سطح دسترسی نیست.

## فاز صفر: خط مبنا و نقشه مؤلفه‌ها

- تطبیق صفحات موجود با فهرست صفحات V2.
- ثبت screenshot و تست‌های baseline برای مسیرهای عمومی و مدیریتی.
- تعیین مؤلفه‌های قابل استفاده مجدد و موارد نیازمند variant جدید.
- نهایی‌کردن قرارداد داده برای متا، حجم موتور، تقویم و داشبوردها.

**خروجی:** نقشه مسیرها، مؤلفه‌ها و قرارداد داده؛ بدون تغییر ظاهری Production.

## فاز یک: توکن‌ها و پوسته‌ها

- افزودن توکن‌های V2 به Tailwind بدون حذف ناگهانی توکن‌های فعلی.
- به‌روزرسانی تدریجی `x-layouts.public` و `x-layouts.admin`.
- مؤلفه‌های پایه: button، card، badge، input، tabs، table/card list، chart shell، empty/error state.
- پوشش dark، RTL، focus و responsive.

**معیار پذیرش:** Story/test page مؤلفه‌ها در viewportهای هدف بدون overflow و با keyboard navigation کامل.

## فاز دو: وب عمومی

1. فهرست خودروها و فیلترها
2. جزئیات خودرو و نمایش سه‌گانه هزینه
3. محاسبه‌گر یک‌صفحه‌ای
4. پیگیری درخواست
5. متا تایتل و متا دیسکریپشن

**معیار پذیرش:** استخراج/نمایش عنوان، برند، مدل، سال، قیمت، کارکرد، حجم موتور و تصاویر برای منابع پشتیبانی‌شده؛ عدم نمایش کارمزد ممنوعه؛ تست موبایل و دسکتاپ.

## فاز سه: پنل مدیریت و نقش‌ها

1. داشبورد مدیریت
2. داشبورد فروش و کانبان شخصی
3. تقویم جلسات و تماس‌ها
4. داشبورد محتوا و صف کنترل کیفیت آگهی
5. صفحات فعلی آگهی، وبلاگ، اسلایدر، منو، نرخ ارز، کاربران و لاگ

**معیار پذیرش:** نقش‌های admin، content و sales فقط داده و عملیات مجاز را می‌بینند؛ جداول در موبایل به نمای قابل استفاده تبدیل شده‌اند.

## فاز چهار: وب موبایل

- اجرای چیدمان‌های موبایل تأییدشده برای تمام صفحات فاز دو و سه.
- نوار پایین، drawer مدیریت، CTAهای sticky و safe area.
- حذف اسکرول افقی سند و تست دستگاه‌های کوچک.

## فاز پنج: Android

- تبدیل قالب تأییدشده به مؤلفه‌های بومی Android/Material 3 در پوسته موجود.
- خانه، خودروها، جزئیات، محاسبه و درخواست من.
- اتصال به API مرکزی، مدیریت loading/offline/error و اعلان وضعیت درخواست.
- عدم تکرار فرمول قیمت‌گذاری در اپ.

## فاز شش: QA و پذیرش Staging

- visual regression برای صفحات مرجع.
- Playwright responsive و accessibility.
- تست نقش‌ها، فرم‌ها، RTL، متن ترکیبی، timezone و تقویم.
- تست منابع DubiCars، YallaMotor و Dubizzle.
- تست Android build و مسیرهای اصلی روی emulator/device.
- ثبت artifact، commit، checksum و گزارش پذیرش Staging.

## ساختار پیشنهادی GitHub

- Epic/Project: `NavraCar V2 Design Implementation`
- Milestoneها: Foundations، Public Web، Admin & CRM، Responsive، Android، Staging Acceptance
- هر صفحه یا مؤلفه مهم یک Issue مستقل با لینک به این سند و تصویر مرجع داشته باشد.
- هر PR باید کوچک، قابل برگشت و دارای screenshot قبل/بعد و نتایج تست مرتبط باشد.

## چک‌های الزامی پیش از Merge

```text
composer install
composer audit
npm ci
npm audit
npm run build
php artisan test --compact
npm run test:e2e
```

برای تغییرات Android، build و تست‌های Gradle/Capacitor مرتبط نیز اجرا شوند.

## تعریف Done

- صفحه با تصویر و مشخصات مکتوب هم‌راستا است.
- RTL، keyboard، touch target، contrast و حالت‌های loading/empty/error تأیید شده‌اند.
- در public UI فقط سه دسته هزینه مجاز دیده می‌شود.
- authorization سمت سرور و داده شخصی بازبینی شده‌اند.
- تست‌های مرتبط سبز هستند.
- روی Staging پذیرفته شده و artifact دقیق برای promotion مشخص است.
