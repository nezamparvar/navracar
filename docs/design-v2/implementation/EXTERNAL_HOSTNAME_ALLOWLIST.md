# External Hostname Allowlist — Batch 1 Evidence Infrastructure

**Purpose:** Enforce strict control over external resources loaded during screenshot generation for visual parity evidence. Only explicitly allowlisted hostnames may have certificate errors ignored; all other failures cause screenshot generation to fail.

**Status:** Batch 1 enforcement active  
**Last Updated:** 2026-08-18  
**Scope:** `tests/e2e/screenshot-generator.mjs`

## Rationale

Batch 1 priority routes (homepage, vehicle-list, vehicle-detail, calculator, admin-dashboard, sales-dashboard) must not depend on external resources beyond the controlled sandbox environment. A permissive allowlist allows uncontrolled external dependencies to silently fail during screenshot capture, masking integration issues.

This enforcement:
1. **Prevents silent failures** — any external request that fails causes screenshot generation to fail loudly
2. **Documents dependencies** — if a route requires an external resource, that resource must be explicitly approved and listed
3. **Maintains determinism** — fixtures and screenshots are reproducible with known inputs, no hidden external state
4. **Supports evidence audits** — reviewers can verify that locked-reference screenshots were generated without unauthorized external integrations

## Enforcement Rules

1. **Localhost/127.0.0.1 Certificate Errors:** ALWAYS FAIL
   - These are the application server itself — certificate errors here indicate misconfiguration, not external resource issues
   - Never suppress

2. **Allowlisted External Hosts:** ALLOW cert errors only
   - If host is in the allowlist AND error is cert-related (`ERR_CERT_AUTHORITY_INVALID`), suppress the error
   - Other error types (connection refused, timeout, etc.) still cause failure

3. **Non-Allowlisted External Hosts:** ALWAYS FAIL
   - Certificate errors: rejected (host not approved)
   - Other errors: rejected

4. **Non-Cert Errors:** ALWAYS FAIL
   - Timeouts, connection refused, DNS failure, etc. — all block screenshot generation
